# Disposable synthetic server-01 staging

This CI job boots fresh copies of the public [AI](../../modules/ai/ollama-open-webui/README.md), [fictional metrics](../../modules/observability/synthetic-metrics/README.md), and [catalog](../../modules/catalog/homepage/README.md) Compose projects on a GitHub-hosted runner. It uses only original `.invalid` links, fictional metrics, generated test credentials, and disposable named volumes. It mounts no Docker socket into an app and never reads an operator host or backup location. The runner is discarded after the job.

The workflow runs on same-repository PRs and `main` pushes with `contents: read`; fork PRs do not start this job. It pulls six upstream version tags selected from their public release lists, records the resolved registry digests in the run, then supplies those digests to the modules' blank image inputs. A tag may resolve to a different digest in a later run; compare receipts before treating runs as the same software snapshot. The test installs a pinned Playwright package and Chromium in the disposable runner. No GitHub secret, pre-existing model data, private route, or live application data is supplied.

`run.sh` resolves Compose and starts separate projects. `check_runtime.py` checks running loopback bindings, Ollama's empty model list, WebUI-to-Ollama reachability, fictional Prometheus ingestion and mode changes, Grafana provisioning, and signed-out API denial using disposable accounts. `check_browser.js` checks that Homepage's fictional cards, WebUI's login screen, and Grafana's login and synthetic dashboard render in Chromium. The scripts print bounded PASS/FAIL summaries without account tokens, passwords, app logs, or screenshots. A failed step remains a failed hosted run; the scripts do not retry it, delete volumes, or relabel it as accepted.

After those checks, `check_recovery.py` restarts the AI project and verifies the fictional owner can still sign in. It then stops both AI services, writes a fixed marker into the model volume, and archives the two quiesced volumes into a private temporary directory on the runner. A helper container uses the already resolved Python image, no network, and read-only mounts for the source volumes. It restores into fresh volumes under a **different Compose project name**, with the same temporary WebUI key and a different loopback port. The test checks the model-volume marker, the original fictional session, a fresh owner sign-in, second-signup denial, signed-out denial, loopback bindings, and WebUI-to-Ollama reachability. It never uploads the archives as CI artifacts. The runner and archives are discarded after the job.

The archive helper is bounded to 4 GB per volume and accepts regular files, directories, and relative symlinks that resolve inside the same volume. It refuses links outside the volume, unsafe archive entries, and nonempty restore targets. These limits suit this fictional fixture; they are not a general backup tool for reader data.

After that model-free recovery exercise, `check_inference.py` deliberately pulls [SmolLM2 135M Instruct](https://ollama.com/library/smollm2:135m) into the **restored disposable Ollama project**. Ollama listed the tag as 271 MB with identifier `9077fe9d2ae1` on 2026-10-30; the [upstream model card](https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct) identifies the model license as Apache 2.0. The first hosted run resolved full digest `9077fe9d2ae1a4a41a868836b56b8163731a8fe16621397028c2c76f838c6907`, now required exactly before generation. The job also rejects a model outside its size bound, an additional installed model, or a Docker GPU device request. It then reaches Ollama from the WebUI container, sends only a fixed fictional prompt with a 32-token limit, and checks for a completed, nonempty response. The model's full resolved digest and fixed PASS/REVIEW labels are logged; prompt output and pull progress are suppressed. The model is fetched by the runner and is not redistributed in this repository or uploaded as a CI artifact. A later tag change must be reviewed rather than silently accepted.

The checked-in [earlier staging receipt](RESULTS.md) predates recovery and inference. Use the specific completed workflow run on a commit containing `check_recovery.py` and `check_inference.py` as evidence for these new checks.

| Acceptance boundary | Scope |
| --- | --- |
| Native containers, browser DOM, fictional metrics, disposable login denial | Checked only when hosted job succeeds |
| Fictional WebUI restart, two-volume archive and separate-project restore | Checked only when the new hosted recovery job succeeds |
| Reviewed small-model pull and nonempty CPU inference through the internal WebUI-to-Ollama route | Checked only when the new hosted inference job succeeds |
| GPU use, reader-selected models, real private route, physical device | NOT RUN |
| Long-term retention, a real-model restore, upgrades, real host recovery and policy | NOT RUN |

This job costs runner time and registry bandwidth. It is a reproducible teaching check, not a model-quality evaluation, security certification, or evidence that a reader's host works. Keep real destinations and all operator backup information out of the public repository. The archive method follows [Docker's volume backup and restore guidance](https://docs.docker.com/engine/storage/volumes/#back-up-restore-or-migrate-data-volumes); readers must choose and test their own protected recovery process privately. Upstream release tags and docs were checked 2026-10-30; [Homepage Docker](https://gethomepage.dev/installation/docker/), [Open WebUI quick start](https://docs.openwebui.com/getting-started/quick-start/), [Ollama Docker](https://docs.ollama.com/docker), [Prometheus installation](https://prometheus.io/docs/prometheus/latest/installation/), and [Grafana Docker](https://grafana.com/docs/grafana/latest/setup-grafana/configure-docker/) remain the operator references.
